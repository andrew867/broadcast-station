# Fresh Intel live-session package test

Tested on 26 October 2026 in Newfoundland time, continuing into 27 October UTC. This record qualifies the prebuilt Intel rendering path in a fresh EndeavourOS live session. It does not qualify persistence across an installed operating system's reboot.

## Environment and isolation

The T480s booted removable EndeavourOS media through Ventoy. Its Intel UHD 620 used the host `i915` driver, kernel `7.1.8-arch1-3` and Mesa `26.1.7`. The session had approximately 15.37 GiB of physical memory, no swap and a 10 GiB RAM-backed writable root overlay. The full ISO digest was not collected; kernel and installed package identities were recorded.

Docker was absent at the start. No previous station configuration, image store, provider credentials or native build dependencies were imported. All internal NVMe partitions remained unmounted, verified before and after the test. Production continued separately at its established UHD30 baseline.

The ISO's package database referenced versions that had left the ordinary mirrors. Five matching packages were obtained from the Arch Linux Archive and passed the package manager's signature and integrity checks: Docker `29.7.2`, Compose `5.4.0`, containerd `2.3.3`, runc `1.5.1` and libpathrs `0.2.5`. This was a disposable-session workaround, not advice to pin those versions for a maintained installation. Docker's initial startup also waited for the live system's network-online dependency.

## Installer defect and storage workaround

Docker's containerd image store could not extract image whiteouts onto the live root overlay. It reported `failed to convert whiteout file: operation not permitted`, but returned success and retained matching image identities. The original bundle verifier therefore printed an inaccurate successful-load result.

The corrected verifier checks each image ID and then starts `/bin/true` from that immutable image. The probe has no network, a read-only root filesystem, no Linux capabilities and no station mounts. A failed unpack now prevents verification success. Ten targeted tests passed, including a matching-ID/failed-start regression case.

Both Docker and containerd were moved to a separate 6 GiB tmpfs mounted at `/run/station-store`. This avoids nesting their writable snapshot filesystem inside the live root overlay. The installed disks remained untouched. The image store used about 3.22 GiB after loading; its configured capacity was a limit, not an allocation of the entire 6 GiB. The complete station, original failed store, downloaded bundle and evidence all fitted in RAM for this bounded run.

The frozen runtime manifest remained unchanged, SHA-256 `bebe296e33d2a72fbdce3a973e5291ab7a27fca38d947b4353841a88a54331e5`. The corrected verifier was supplied separately and checked all ten original assets. Both image-start probes passed after the storage repair. The controller and engine identities remained those recorded in [package acceptance](PACKAGE-ACCEPTANCE-20261026.md); neither application image was rebuilt.

## Evidence and restoration

The private evidence archive includes the original environment inventory, native and full-programme recordings, probe reports, screenshots, final container/image identities and restart/configuration checks. It was copied off RAM and verified before shutdown. Its SHA-256 is `7b82a4037c0f7e953a91dce64f1b94799994b28ebecffda7919cc6ed52cb4910`.

The temporary public-key and package HTTP servers were stopped. The live session was shut down normally, the USB was removed and the installed standby system was booted. Its display manager remained inactive, with no desktop session. The headless launcher, watchdog, relay, rundown and generated music recovered. The four saved configuration hashes and both application image identities matched the pre-test checkpoint.

An independent 90-second recording at the MediaMTX receiver passed complete decoding, measured 30.000 video packets/s, non-silent 48 kHz AAC audio, stream coverage and timestamp checks. No large video or audio gaps were found. The first inspected camera frame showed a signal-recovery banner, and subsequent source-health checks recorded intermittent STJ West decoder recovery. That source-continuity issue remains open; successful programme delivery does not establish that every camera stayed fresh. Production remained at its UHD30 baseline.

The image-loader repair passed private CI run `40426466102` at source revision `306270acf5fd342068ec75b8f8a766ea6defbe2b`. The live evidence and installed-system restoration reports are retained in the verified private checkpoint archive.

A clean persistent GPU installation remains an open acceptance boundary. The existing Intel no-login reboot test and this fresh live-session test provide complementary evidence; neither makes the other a clean installed-OS reboot test.
